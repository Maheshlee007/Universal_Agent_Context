# UAC 0.6.0 Chapters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every save becomes a permanent chapter of its session, so long sessions stop losing their early work. Open items carry forward in code, and the next session sees the latest chapter plus an index of earlier ones.

**Architecture:** A chapter is a `summaries` row linked to its checkpoint (`checkpoint_id`, `from_ts`). `save()` stops replacing: it writes the chapter and computes the carried open items. `digest()` pages instead of truncating and sends numbered `open_items`. `fmtCard()` renders `chapter N/N`, the session goal, the latest chapter and one line per earlier chapter. `uac_get` opens a chapter by its `s-` id.

**Tech Stack:** Node 22 ESM, node:sqlite, node:test. Zero dependencies.

## Global Constraints
- LLM-facing only: no dashboard or viewer changes (user, 2026-09-30).
- Zero npm dependencies; node:sqlite only.
- Every save is still ONE `uac_save` call. No compressor multi-page loop: the next Stop picks up the next page.
- Earlier-chapter index lines count inside the existing 45% card budget of `bootstrap`.
- Version: 0.6.0 in `package.json`, `plugin/.claude-plugin/plugin.json` and `extension/package.json`.

## File map
- `plugin/src/db.mjs`: migration columns `summaries.checkpoint_id`, `summaries.from_ts`.
- `plugin/src/store.mjs`: `card()` uses the linked checkpoint; new `chapters(sessionId)`; PROJECT.md shows the latest chapter per session.
- `plugin/src/pack.mjs`: `digest()` pages and sends open items; `save()` writes chapters and carries open items; `fmtCard()` gets chapter rendering; `HOW_TO_SAVE`.
- `plugin/src/mcp.mjs`: `uac_get` for chapters and a session's chapter list; the `uac_save` schema gets `checkpoint.closed`.
- `plugin/agents/uac-compressor.md`: the chapter contract.
- `test/core.test.mjs`: one chapters test that replaces "large session digest…".

```js
// A session's chapters, oldest first: one per LLM save, each about ITS events only (cards saved before 0.6.0 are
// whole-session rewrites: `pre`, they overlap later ones)
export function chapters(sessionId) {
  return all(`SELECT x.id, x.title, x.from_ts, x.created_at AS at, x.events_n, COALESCE(x.checkpoint_id,
      (SELECT c.id FROM checkpoints c WHERE c.session_id = x.session_id AND c.trigger = 'save' AND c.ts >= x.created_at ORDER BY c.ts LIMIT 1)) AS cp
    FROM summaries x WHERE x.session_id = ? AND x.quality = 'llm' ORDER BY x.created_at`, sessionId)
    .map((r, i) => { const c = r.cp ? get('SELECT goal, files FROM checkpoints WHERE id = ?', r.cp) : null;
      return { id: r.id, no: i + 1, title: r.title, from_ts: r.from_ts, at: r.at, events_n: r.events_n, goal: c?.goal ?? null, files: P(c?.files, []), pre: !r.from_ts }; });
}
```

Drop any carried item whose text (tag stripped) equals a new step. Store `[...new, ...carried]` as the checkpoint's `next_steps`, BEFORE `addCheckpoint`.
